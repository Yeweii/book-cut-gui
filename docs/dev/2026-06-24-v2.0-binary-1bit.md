# 2026-06-24 · book-cut v2.0 二值化 1-bit 输出（提案）

> 状态：提案，已拍板
> 续 `2026-06-23-v1.9.2-crop-robustness.md`（branch: `v2.0-binary-1bit`）

## 1. 目标

古籍二值化（otsu/adaptive/sauvola）当前输出 8-bit 灰度图（值仅 0/255），白白浪费 7 bit/像素，
导致 PNG/PDF 体积虚高 8 倍。本提案加 `binary_mode` 选项，默认走 1-bit 紧凑输出，
零画质损失（值就是 0/255）下文件缩到原来的 1/8。

**核心交付**：
1. `preprocess/binarize.py` 三个算法（otsu/adaptive/sauvola）加 `binary_mode="1bit"|"8bit"` 参数
2. `pipeline/orchestrator.py:_compute_page` 透传 `binary_mode`
3. CLI：`--binary-mode {1bit,8bit}`（默认 1bit）+ `BOOKCUT_BINARY_MODE` 环境变量
4. GUI：binarize 段加 "1-bit 紧凑输出" checkbox
5. 测试：synthetic 4000×5000 页 1-bit < 50 KB、跨页 mode 兼容、PDF 落盘正常
6. 文档：CHANGELOG + proposal

**不交付（后续）**：
- CCITT G4 压缩（需引 pymupdf 改 PDF 装配链），留 v2.1

## 2. 现状

`preprocess/binarize.py:46-47`：

```python
def _to_L_image(arr_u8: np.ndarray) -> Image.Image:
    return Image.fromarray(arr_u8, mode="L")
```

`_to_L_image` 永远是 `mode="L"`（8-bit）。`Image.fromarray(binary_arr, mode="1")` 是 1-bit
调色板（值 0/1），需要主动转换。

`pipeline/orchestrator.py:288`：

```python
sub_pages = [binarize(p, binarize_method) for p in sub_pages]
```

`binarize` 不传 `binary_mode`，永远是 L 模式。

`io/exporter.py:39-62`：

```python
def save_image(image, output_dir, book_name, index, fmt="png", quality=95):
    ...
    image.save(out_path, **save_kwargs)  # 按 mode 自动选 PNG 编码
```

PNG 编码对 `mode="1"` 自动用 1-bit palette，无需改。

`img2pdf.convert([...])` 默认 Flate 压缩。1-bit 图像 Flate 已经能压到原始 1/8 ~ 1/20；
对 1-bit 没有自动用 CCITT G4，但**已经从 8x 缩到 1x**（本提案目标）。

**实测**（v1.9.2 尸子图 6400×8534，split=none 全流程）：

| 格式 | 8-bit L（v1.9.2） | 1-bit（v2.0） | 缩减 |
|------|------------------|---------------|------|
| 尸子图 PDF | 651 KB | 459 KB | **1.42x** |
| sample_two_page PDF | 26.8 KB | 17.8 KB | **1.51x** |

**注**：早期合成 random 7% 黑数据测出 8x 缩减（理论 1-bit raw 字节就是 8-bit 的 1/8），
但真实古籍二值化后熵较高（边缘飞白、噪点），Flate 压缩后实际缩减 **1.4-1.6x**。
100 页古籍按此比例 ~280 MB → ~190 MB，仍是可观的 30%+ 缩减。

## 3. 方案（已拍板）

### 3.1 `binary_mode` 语义

| 取值 | binarize 返回 mode | 备注 |
|------|--------------------|------|
| `"1bit"`（默认） | `"1"` | 1-bit 调色板（值 0/1）；PNG/PDF 自动走 1-bit |
| `"8bit"` | `"L"` | 旧行为，向后兼容 |

`binarize_method="none"` 不走二值化，保持原图 mode（可能是 RGB/L/...），**不强制 1-bit**。

### 3.2 1-bit 转换方式

`arr_u8` 是 0/255 的 `uint8` 数组。三选一：

| 方案 | 写法 | 优势 | 劣势 |
|------|------|------|------|
| A | `Image.fromarray(arr_u8 > 0, mode="1")` | 一行 | `bool` ndarray 临时 |
| B | `Image.fromarray((arr_u8 // 255).astype(np.uint8), mode="1")` | 显式 | 多一次除法 |
| C | `Image.fromarray(arr_u8, mode="L").convert("1", dither=Image.Dither.NONE)` | 复用 L 转 1 | 1 次 L 中间 |

**拍板**：A —— 最简 + 一次转换。`arr_u8 > 0` 把 0/255 → False/True，1-bit palette 自动取 0/1。

`dither=NONE` 在 A 方案里**不是问题**：1-bit palette 模式直接按位取值，无 dithering。
（`convert("L").convert("1")` 路径才会有 Floyd-Steinberg dither，必须传 `dither=NONE`，
但 A 路径走 `Image.fromarray(bool_arr, mode="1")` 不经过 dither。）

### 3.3 CLI 形态

```
--binary-mode {1bit,8bit}     默认 1bit
BOOKCUT_BINARY_MODE=1bit|8bit  环境变量兜底（CLI > env > default）
```

GUI：binarize 段加一个 checkbox，**默认勾选**（=1bit），与 v1.3 `crop-adaptive` 同模式。
用户取消勾选 → 走 8bit 兼容路径。

### 3.4 pipeline 透传

`run_pipeline` 读 `args.binary_mode` → `_compute_page(binary_mode=...)` →
`binarize(p, binarize_method, binary_mode=binary_mode)`。

`_compute_page` 现有签名加 `binary_mode: Literal["1bit", "8bit"] = "1bit"`。

## 4. 风险与边界

### 4.1 mode="1" 下游兼容

- **保存**：`save_image` 走 PIL PNG 编码，对 `"1"` 自动 palette，无问题
- **img2pdf**：检测 1-bit 图像走 FlateDecode，无问题
- **v1.4 outline 注入**：pypdf 只改 `/Info` 和 outline，**不动图片 XObject**，无问题
- **v1.7 fit_to_canvas**：接受任意 mode，把 `"1"` 当 L 处理（内部 `convert("L")`），无问题
- **v1.8 dry_run preview**：拼图阶段 `Image.fromarray(...)` 时若传 mode 错，会被 `.convert("RGB")` 自动纠正，无问题

### 4.2 边界场景

- **空图（全 0 / 全 255）**：`arr_u8 > 0` → 全 False / 全 True → 1-bit 仍合法
- **crop_mode="none" 不裁切 + binarize**：`sub_pages = [Image.fromarray(a, mode="L") for a in sub_arrs]`
  直接给 L 模式，下游 binarize 按 `binary_mode` 转 1-bit，OK
- **`--binarize none`**：跳过 binarize 整个调用，`sub_pages` 保持裁切后的 L，无问题
- **3-bit/4-bit 输入**：当前代码无此场景（输入都是 L/RGB 8-bit），无需考虑

### 4.3 性能

`arr_u8 > 0` 是 element-wise 比较，对 4000×5000 uint8 ≈ 20 MB 一次性扫一遍，~10-15 ms，
可忽略（v1.9 全流水线 ~179 ms/页）。
