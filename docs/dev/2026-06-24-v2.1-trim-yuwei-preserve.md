# v2.1 trim D 方案：版心保护区（保留鱼尾等版心装饰）

> 日期：2026-06-24 · branch `v2.1-trim-ab`
> 提案背景：实验报告 `2026-06-24-v2.1-trim-ab-experiment.md` §5.5 用户反馈
> "鱼尾内的还是被裁剪了"，根因为 CCA 把鱼尾装饰条当作版框线/小连通区滤掉。

## 1. 问题

v2.1 A+B+C（`--trim-source binarized` + `--trim-min-component-ratio 0.0001` +
`--trim-padding 60~120`）在尸子图上仍裁掉**底部鱼尾**：

| 方案 | 输出 H | 鱼尾保留？ |
|------|-------|-----------|
| baseline (无 B) | 7610 | ❌ 版框线未被滤，无关 |
| B only | 5707 | ❌ 鱼尾被滤 |
| B+C extra60 | 5827 | ❌ 鱼尾仍被滤（mask 已不含鱼尾） |
| B+C extra120 | 5947 | ❌ 同上 |
| **B+C+D** (本方案) | **7603** | ✅ 鱼尾保留 |

## 2. 根因

CCA `_filter_main_components` 用两条规则过滤连通区：
1. `area < min_area` → 滤（小噪点）
2. `aspect > 10` → 滤（狭长版框线）

**鱼尾装饰条同时命中两条规则**：
- 鱼尾主体边框线：`aspect ≈ 28-55`（狭长）→ 被 aspect 滤
- 鱼尾小碎片：`area ≈ 1-25`（小）→ 被 area 滤
- 加 `extra_padding` 无法挽救 —— mask bbox 已在 CCA 后排除鱼尾

## 3. 方案 D：版心保护区

**核心思路**：版心是结构化区域（鱼尾、卷名、页码所在地），不应套用面向边缘的 CCA 规则。

**检测**：版心带是 `(left_frac, right_frac)` 占宽度的区间。语义：
- 未分割图像 → `0.4, 0.6`（中央）
- 分割后左页 → `0.7, 1.0`（右侧，鱼尾在折页中线侧）
- 分割后右页 → `0.0, 0.3`（左侧，鱼尾在折页中线侧）

**CCA 豁免逻辑**（`src/book_cut/detect/trim.py:_filter_main_components`）：
- 连通区 bbox **中心列**落在 gutter_band 内 → 视为版心装饰
- **area 阈值豁免到 4 px²**（只滤 1-3 px 单像素噪点）
- **aspect 阈值豁免**（保留鱼尾装饰条的横向长条）

**边缘连通区不受影响**：
- bbox 中心在版心外 → 走原 area + aspect 双过滤
- 版框线（col < 版心带）正常被 aspect 滤掉

## 4. CLI 用法

```bash
# 尸子图场景（鱼尾在 col 2558，gutter 0.35-0.5 覆盖）
book-cut \
  --input 尸子图.png \
  --output out/ \
  --split none \
  --crop trim \
  --trim-source binarized \
  --trim-min-component-ratio 0.0001 \
```

## 7. 方案 E：adaptive padding 覆盖（紧度微调）

> 日期：2026-06-24 · 用户反馈 "鱼尾保留，但上下空白反而增加太多"
> 根因：方案 D 后鱼尾保留完整，但 adaptive padding 默认 30 px（cap）+ `--trim-padding 30` extra = 60 px 每边
>      上下空白看起来过宽。

### 7.1 根因

方案 D 让 mask bbox 完整包含鱼尾/版心装饰。但 trim 输出还在 bbox 基础上加 padding：
- `adaptive_padding(h, w)` = `max(5, min(30, int(min(h,w)*0.02)))` → 6400×8534 → cap 30
- 叠 `--trim-padding 30` → 60 px 每边 → 输出 7601
- 用户期望"紧" → 砍掉 adaptive 部分

### 7.2 方案

新增 **`--adaptive-padding N`** flag（v2.1+）：
- 默认 `None` = 走公式（v1.9 行为，cap 30）
- 设值后 = N 像素（opt-in 覆盖）
- 设 0 = 完全贴 mask bbox（最紧，节省 60 px）
- 设 30~60 = 加保护边（防止鱼尾/边栏贴边）
- 仅 `--crop-adaptive auto` 生效

### 7.3 实测（尸子图，方案 D 基础）

| 配置 | 输出 H | Δ vs D 默认 | 鱼尾 |
|------|--------|------------|------|
| D 默认（adaptive=30 + trim-padding=30） | 7603 | — | ✅ |
| **D + `--adaptive-padding 0`**（默认 + 紧） | **7543** | **-60** | ✅ |
| D + `--adaptive-padding 0 --trim-padding 0` | 7483 | -120 | ✅ |

样本：`samples/test/trim_adaptive_padding/尸子_D_*.png`（3 张对比图）

## 8. 方案 F：--split none 保留全宽（双页扫描不切分场景）

> 日期：2026-06-24 · 用户反馈 "按B来" —— 双页扫描用 `--split none` 时，
> trim 默认横向也裁，会丢右侧副页/版框线。

### 8.1 根因

`--split none` 语义是"输入已是单页"，但 trim 仍按 `horizontal=True`（默认）
跑全 bbox 裁切 → 双页扫描会被裁掉右侧内容（版框线/副页/鱼尾等）。

| 模式 | 输入 W | 输出 W | 横向裁切？ |
|------|-------|--------|-----------|
| `--split gutter` + `--crop trim`（默认） | 6400 | 2909 / 1618（左右页） | ✅（split 已分） |
| `--split none` + `--crop trim`（v2.1 D） | 6400 | **2829**（丢右侧 ~3500 px） | ✅（默认） |
| `--split none` + `--crop trim`（本方案 F） | 6400 | **6400** | ❌（保留全宽） |

### 8.2 方案

新增 `horizontal` 参数（v2.1+ F）：
- `horizontal=True`（默认）：全 bbox 裁切（v1.9 行为）
- `horizontal=False`：只裁上下，保留输入全宽

CLI 不直接暴露，由 `run_pipeline` 自动推断：
```python
horizontal: bool = (args.split != "none")
```
- `--split none` → `horizontal=False`（保留全宽）
- 其他 split → `horizontal=True`（默认）

### 8.3 实测（尸子图，方案 D + adaptive-padding 0 基础）

| 配置 | 输出 W | 输出 H | 右侧版框线？ |
|------|--------|--------|------------|
| D + --split gutter（v2.1 默认） | 2909 / 1618 | 7552 / 7079 | ❌（已 split） |
| **D + --split none + horizontal=True**（v2.1 D 行为） | **2829** | **7543** | ❌（被裁） |
| **D + --split none + horizontal=False**（本方案） | **6400** | **7543** | ✅ |

样本：`samples/test/trim_split_none_尸子_全宽.png`（6400×7543）

## 9. 方案 G：多 band 豁免（双页扫描右侧副页保留）

> 日期：2026-06-24 · 用户反馈 "A+B 效果更好，只是将右侧鱼尾给裁剪掉了，后续基于 A+B 优化"
> 根因：方案 D 单 band 只覆盖中央版心，无法保留右侧副页 / 装饰。

### 9.1 根因

方案 D 的 `--trim-gutter-band L,R` 是**单 band**，仅在版心列带豁免 CCA aspect 过滤。
双页扫描 + `--split none` 场景下，右侧副页（col 3500-4800）的版框线 / 装饰被 aspect 滤掉
→ bbox 退回到主页面右边界 → 右侧内容丢失。

| 配置 | 输出 W | 输出 H | 右侧副页 |
|------|--------|--------|----------|
| A+B（无 band） | 2829 | 5707 | ❌（aspect 滤） |
| D（单 band） | 3939 | 7543 | ❌（band 范围外） |
| **G（多 band）** | **4889** | **7554** | ✅（双带覆盖中央 + 右侧） |

### 9.2 方案

新增 `gutter_bands: list[tuple[float, float]]`（v2.1+ G）支持多个保护带：

```python
# 旧 API（单 band，向后兼容）
gutter_band: tuple[float, float] | None = None

# 新 API（多 band，推荐）
gutter_bands: list[tuple[float, float]] | None = None

# 两者共存时内部合并为统一 list
```

**CCA 豁免逻辑**（`_filter_main_components`）：
- 连通区 bbox 中心列落在**任一** band 内 → 视为版心装饰
- 仍受 min_area 阈值约束（仅滤 1-3 px 噪点）
- aspect 阈值豁免（保留鱼尾装饰条）

## 10. 局限与后续

1. **gutter_band 需手动设置**：当前无自动检测（CLI `--trim-gutter-band auto` 暂等同关闭）。
   - 后续：split 后根据 split_x + page_order 自动推断（左页 → `0.7,1.0`；右页 → `0.0,0.3`）
2. **多 band 顺序敏感**：当前 CCA 遍历 list 顺序不影响结果（任一匹配即豁免），但 CLI 字符串需按列位置顺序书写（如 `0.0,0.1,0.4,0.6` 而非 `0.4,0.6,0.0,0.1`）。
3. **仅过滤 aspect + area**：版心区内的连通区全部保留（除 1-3 px 噪点），可能误保留某些罕见噪点。后续：版心区内可加密度/形状检测
4. **split 模式下 band 坐标空间**：当前 band 应用于 sub-arr 坐标空间（非原图）。
   若 `--split gutter` 后想保留跨 gutter 的版心装饰，需 `--split none` + 多 band
   （或在 splitter 层传递原图坐标）
5. **`horizontal` 仅 split none 时关闭**：若用户想"split gutter + 保留全宽"（合并左右页为一张图），需加 `--horizontal` flag override
6. **未在多本古籍验证**：仅在尸子图 + 合成图上验证。其他古籍（茶山集、ZHSY100456）需补充样本测试

## 11. 方案 B（strict 后置过滤）：排除稀疏页眉/页脚

> 日期：2026-06-24 · 用户反馈 "A+B 还是有点宽，比参考图多了 200px"
> 根因：A+B 把页眉/页脚的稀疏字符纳入了 bbox（顶部 ~150 px + 底部 ~50 px）。

### 11.1 问题

A+B（`--trim-source binarized` + `--trim-min-component-ratio 0.0001`）默认把页眉
（顶部卷名/章节标题）和页脚（页码/版权）的稀疏字符也纳入 bbox：

| 配置 | 输出 H | 参考图 H | Δ |
|------|--------|---------|---|
| baseline (无 B) | 7610 | 5707 | +1903 |
| A+B | 5910 | 5707 | +203 |
| **A+B+strict** | **5855** | 5707 | +148 |

页眉（rows 1700-1849）：~13 ink/row（极稀疏字符）
页脚（rows 7557-7610）：~30 ink/row（稀疏边界）

这些字符 per-row ink 远低于主体正文（~700 ink/row），应被排除。

### 11.2 方案

新增 **`--trim-strict`** flag（v2.1+ B 方案）：

**算法**：trim 输出前对 `ink_mask` 做后置过滤：
1. 计算 `row_ink = ink_mask.sum(axis=1)`
2. `max_row_ink = max(row_ink)`
3. `strict_threshold = max(50, int(max_row_ink * 0.1))`
4. `row_has_content = (row_ink >= strict_threshold)`

> **关键**：strict 在 CCA 之后运行。CCA 已经过滤掉大部分页眉/页脚小字符，
> strict 进一步过滤掉 CCA 漏网的稀疏行（如边界外的小连通区）。

**CLI 默认 False**（向后兼容 v2.1 A+B 行为）。

### 11.3 CLI 用法

```bash
book-cut \
  --input 尸子图.png \
  --output out/ \
  --split none \
  --crop trim \
  --trim-source binarized \
  --trim-min-component-ratio 0.0001 \
  --trim-strict            # 新增 flag
```

### 11.4 实测（尸子图 6400×8534）

| 配置 | 输出 W | 输出 H | Δ H vs A+B | 页眉/页脚 |
|------|--------|--------|-----------|----------|
| A+B (无 strict) | 6400 | 5910 | — | 保留 |
| **A+B+strict** | 6400 | **5855** | **-55** | 部分排除 |
| 参考图 | 6400 | 5707 | -203 | 全排除 |

注：strict 单独只减 55 px，因 CCA 已过滤掉大部分稀疏字符。
剩余 148 px 差距来自页眉版框线（rows ~1700 上方）被 CCA 当作 main body 的一部分保留
（与主体粘连）。完全紧贴参考图需结合方案 D/E（adaptive-padding + gutter-band）
或更激进的 CCA 阈值。

### 11.7 向后兼容

- `--trim-strict` 默认 False → 行为与 v2.1 A+B 一致
- 函数签名 `strict: bool = False` → 旧调用代码无需修改
- 与方案 A/B/C/D/E/F/G 完全正交，可与任意组合叠加

1. **gutter_band 需手动设置**：当前无自动检测（CLI `--trim-gutter-band auto` 暂等同关闭）。
   - 后续：split 后根据 split_x + page_order 自动推断（左页 → `0.7,1.0`；右页 → `0.0,0.3`）
2. **多 gutter 区域支持**：当前只支持 1 个 gutter band。古籍有时有"书耳"或"边栏"装饰（多 gutter 区）→ 后续扩展为 `gutter_bands: list[tuple[float, float]]`

4. **`horizontal` 不暴露 CLI**：当前由 split 模式自动推断。若用户想"split gutter 但保留全宽"（合并左右页为一张图），需加 `--horizontal` flag override
5. **未在多本古籍验证**：仅在尸子图 + 合成图上验证。其他古籍（茶山集、ZHSY100456）需补充样本测试
