# 2026-06-25 · v2.4 手动切分线（--split manual + --pick-split-line）

## 背景

古籍双页扫描的自动切分（gutter / border）在以下场景失效：
- 书脊歪斜 → 列投影最白段偏离真实中缝
- 中缝飞墨 → 中缝被墨迹占据，列投影找到假"白段"
- 版框断裂 → Hough 找不到完整版框

用户反馈：需要一种"我告诉你切哪里"的手动方案。

## 决策

- **D1**：每本书一条切分线（per-book profile），不每页选
  - 古籍装订后左右页物理位置固定，整本书同一中缝
- **D2**：JSON v1 schema（`{"version": 1, "split_x", "source_size", "page", "deskew_applied", "notes"}`）
- **D3**：preset 必须记 `deskew_applied`，与 `args.deskew` 不一致触发 MS009 错误
  - deskew 改变坐标系，跨状态复用 preset 切分 x 会偏移
- **D4**：MSxxx 错误码统一系列：MS001（split_x 越界）/ MS002（非整数）/ MS003（size mismatch）/ MS004（missing）/ MS005（file 不存在）/ MS006（version）/ MS007（单页）/ MS008（1:3+ 多子图）/ MS009（deskew 不一致）
- **D5**：`--split manual` + 单页检测 → warn MS007 + 跳过切分（输出 [整图]）
- **D6**：`--split manual` + 1:3+ 异常（>2 子图）→ warn MS008 + fallback gutter（不报错）
- **D7**：`--pick-split-line` 子命令走 GUI；GUI 主窗新增「手动（画线）」radio + 「选切分线...」按钮

## 已知限制

- v2.4 仅支持竖直切分线（古籍左右双页，水平无意义）
- split_x 必须是 post-deskew 坐标系下的整数；preset 与 `--deskew` 必须一致
- GUI 选线弹窗未做撤销栈（仅双击重置到中心 + 重新拖线）
