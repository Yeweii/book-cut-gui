# 2026-06-21 · book-cut v1.4 PDF outline 保留

## 概要

v1.3 及之前版本的 PDF 合并用 `img2pdf.convert()`，**完全丢弃原 PDF 的 outline（书签）和 metadata**。
古籍扫描件 PDF 经常带"卷一/卷二/卷三"等书签目录，v1.4 透传这些信息到输出 PDF，让 PDF 阅读器的侧边栏继续可用。

实现：方案 D —— 复用 img2pdf 出"无 outline 中间 PDF"，再用 pypdf 后处理注入 outline + metadata。
理由：保留 img2pdf 的"无损合并"，改造成本最低。

## 选型理由

| 子项 | 选 | 拒 |
|------|------|------|
| 后处理方式 | pypdf 后处理 | PyMuPDF 全程重写有损；改原 PDF 插入页号偏移难处理 |
| 依赖 | pypdf>=4.0（纯 Python，~1MB） | pikepdf 已有但绑定 libqpdf；自写 pypdf 维护成本低 |
| 1:2 outline 指向 | **只指第一张**（拍板） | 复制成 2 项"卷二（右）/卷二（左）"信息冗余 |
| 页序开关 | `--page-order {ltr,rtl}` | 让繁体竖排古籍用 rtl（右先左后） |
| Metadata 处理 | 默认透传 + Producer 追加 `book-cut` | 完全丢弃（古籍需要保留作者/书名） |
| 多 PDF 源 | 只取第一个 PDF 的 outline + metadata | 智能合并语义模糊，留 v1.5 |
| `--no-outline` | 同时关闭 metadata | 用户心智里 outline+metadata 是一组 |
| Page labels | **不做**（v1.5） | 罗马数字拆分需要先确定页号表达式 |
| PageInfo 接口 | **不**加 toc/metadata 字段 | 提供独立 `get_pdf_outline` / `get_pdf_metadata` 工具函数 |

## 关键决策

### 1. "只指第一张" 拍板的微妙影响

LTR 和 RTL 模式下，**outline 指向的页号完全一样**（如"卷一"原 PDF page 3 都指向输出 PDF page 5）：

- LTR 1:2：sub_pages = [左, 右]；first = 左 → output index 2*(3-1) = 4 (page 5)
- RTL 1:2：sub_pages = [右, 左]；first = 右 → output index 2*(3-1) = 4 (page 5)

页号一致但**实际指向的页内容不同**（LTR 指左页，RTL 指右页）。这符合"只指第一张"的字面定义，也是 outline 该有的语义（书签指"卷一开始"，而不管左/右先出哪个）。

如果用户后来要"指向特定方向"（如"卷一（右）"），可加 `--outline-mode {first,right,left,dup}`。

### 2. PageInfo 不扩展

讨论过的方案是给 `PageInfo` 加 `pdf_toc` / `pdf_metadata` 字段。**最终拒绝**，理由：
- 99% 的 PageInfo 来源是图片/单页加载，根本没 PDF 结构信息
- 加 None 字段是噪音
- outline/metadata 是"全文档级"信息，挂在每页是浪费

改为：提供独立工具函数 `get_pdf_outline(path)` / `get_pdf_metadata(path)`，pipeline 在 PDF 输入时调一次。

### 3. 多 PDF 源 = 只取第一个

文件夹含多个 PDF + 大量图片时，**第一个 PDF（按文件名排序）的 outline + metadata 注入输出 PDF**，其余 PDF 的页参与输出但不挂 outline。

log 警告：`[WARN] 文件夹内含多个 PDF；outline/metadata 仅保留第一个: xxx.pdf`

未来 v1.5 候选：把多 PDF outline 拼成"第一级目录 = PDF 名"。

### 4. pypdf vs pikepdf

项目已有 `pikepdf==10.9.1`（间接依赖），但：
- pikepdf 绑定 libqpdf，PyInstaller 打包要 collect 动态库
- pypdf 纯 Python，~1MB，PyInstaller 自动识别
- 注入 outline 这点功能 pypdf 够用（add_outline_item 支持嵌套）

### 5. Producer 标记

透传 metadata 时，`/Producer` 追加 `"; book-cut {__version__}"` 标记出处：
- 便于用户识别"这个 PDF 是 book-cut 处理的"
- 不丢失原 producer（如 `Adobe Acrobat 15.7`）

### ZHSY100456 真实数据

合成 outline 注入 ZHSY（66 页）：

```bash
python -c "
import pymupdf
doc = pymupdf.open('samples/ZHSY100456_醉翁琴趣外篇_宋歐陽修撰_清初影宋抄本.pdf')
doc.set_toc([
    [1, '封面', 1], [1, '卷一', 3], [1, '卷二', 15], [1, '卷三', 30],
    [1, '卷四', 45], [1, '卷五', 60], [1, '封底', 66],
    [2, '卷一·上', 3], [2, '卷一·下', 9], [2, '卷三·序', 30],
])
doc.set_metadata({'title': '醉翁琴趣外篇', 'author': '宋 歐陽修', ...})
doc.save('/tmp/zhsy_v1.4.pdf')
"

python -m book_cut -i /tmp/zhsy_v1.4.pdf -o samples/out_v1.4 \
  --split gutter --crop border --binarize sauvola --pdf --no-single-page
```

### RTL 验证

`--page-order rtl` 翻转 sub_pages，但 outline 页号不变（"只指第一张"语义）：
- 封面 (orig p1) → output p1（两次都是 first）
- 卷一 (orig p3) → output p5（LTR 指左，RTL 指右，但 index 都是 4）

实际页面内容确实相反（用 pymupdf 渲染 page 5 比较 PNG 字节数 LTR=574, RTL=511，差异明显）。

### --no-outline 验证

`--no-outline` 同时关闭 outline + metadata：输出 PDF 0 节点、Title/Author/Producer 全空。
