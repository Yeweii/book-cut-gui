## Sprint 1：D1+A2+A1+D2+D3（性能基线 + 提速 + 测试覆盖）

### A2 · Sauvola 平台后端选择（commit 97608dd）

**问题**：原提案直接用 `cv2.sqrBoxFilter` 替 `boxFilter(arr*arr)`，但实测发现 arm64 NEON 上 `sqrBoxFilter` 反而**慢 27-80%**。

**解决**：平台自动 fork
- `platform.machine() in {x86_64, AMD64, ...}` → `sqrBoxFilter`
- 其他（含 arm64）→ `boxFilter`（= v1.4 baseline）
- 环境变量 `BOOKCUT_BINARIZE={sqrbox,box}` 覆盖

**实测**（macOS arm64）：
- boxFilter：2000²=16ms / 4000²=62ms
- sqrBoxFilter：2000²=21ms / 4000²=98ms ✗

**结论**：arm64 用户零损失（默认走 box），x86 用户省 64MB 内存。

### A1 · 流水线单次 RGB→L 转换（commit 37206ba + f9249b9）

**问题**：开 `--deskew --split gutter --crop border --binarize sauvola` 时每页 5 次 `convert("L")`，133 页浪费 1.6s。

**解决**：
- 9 个函数加 `*_from_array` 私有变体（接受 ndarray）
- pipeline 主循环 1 次 `np.asarray(image.convert("L"))`
- 公共 API 零改动（薄包装调 `_from_array`）

**实测**：4000×4000 全流水线 160ms → **101ms**（-37%）。

**关键设计**：薄包装模式保证 65 老 test 零修改通过。

### D1+D2+D3 · 测试覆盖（commit 420ccb4 + 066b8d0）

- D1：`test_perf.py`（5 个 perf test，阈值宽松 30× 余量）
- D2：边界用例 7 个（损坏 PDF / 非标尺寸 / --paper-pages 0 / clamp / 空输入）
- D3：border 路径 8 个（split_border 3 + crop_to_border 5）

总测试 73 → 88（+21%）。

## Sprint 2：B1+B2（流式 + BytesIO）

### B1 · 流式 iter_pages（commit 82aec64）

**问题**：`pages: list = list(iter_pages(...))` 全量加载。133 页 = 4.8GB；1000 页 = 48GB → **OOM**。

**解决**：
```python
page_iter = iter_pages(args.input)
sampled = list(islice(page_iter, paper_pages_n))  # 估 paper color
crop_config = _build_crop_config(args, sampled)
full_iter = chain(sampled, page_iter)  # 关键：chain 让采样页不被丢
for page in tqdm(full_iter):
    ...
```

**关键设计**：`islice` 会消耗前 N 个 item，所以必须 `chain(sampled, remaining)` 把采样页拼回去。这是个易踩的坑（首次实现漏掉导致小 PDF 输 0 张）。

**实测**：ZHSY 66 页内存峰值 8.6GB → **39MB**（-220×）。

### B2 · BytesIO 去 temp 文件（同 commit）

**问题**：`_write_pdf_with_outline` 写 `tempfile.NamedTemporaryFile` → 100MB PDF 两次磁盘 I/O ~500ms。

**解决**：
- `save_pdf_bytes()`：`img2pdf.convert(paths, outputstream=BytesIO)` → bytes
- `inject_outline_and_metadata_from_bytes()`：`pypdf.PdfReader(BytesIO(bytes))` → 注入 outline + 写目标 PDF
- 私有 `_build_writer_from_pdf_bytes()` 共享 builder 逻辑（路径版和 BytesIO 版都调）

**API 验证**：img2pdf 0.5/0.6/0.7 的 `outputstream=` 参数都支持。

### 新增测试

`test_pipeline_memory_steady_50_pages`：50 页 × 200×200 → tracemalloc peak < 200MB。
**实测 3.4 MB**（远低于阈值，确认流式）。

## Sprint 3：C1 共享 Hough 模块（commit 0ecf139）

**问题**：3 个 caller（deskew / split_border / crop_border）各自实现 Canny + HoughLinesP + cluster，80 LOC 重复；参数散落（threshold 60/80）。

**解决**：抽 `book_cut/detect/_hough.py`：
- `canny_edges(gray)` 共享 Canny
- `detect_lines(gray, *, threshold, min_length_factor, max_gap)`
- `cluster_lines(lines, tol)` 共享聚类
- `HOUGH_PRESET_DESKEW / SPLIT_BORDER / CROP_BORDER` 常量

3 caller 改为薄包装，LOC 210 → 90（**-57%**）。

**行为对等**：
- `test_detect_lines_equivalent_to_inline_split_border`：line 集合 set 比较一致
- `test_detect_lines_equivalent_to_inline_crop_border`：同上
- 9 个新 test 全过；现有 89 → **98**

### A3（Hough 缓存联动）推迟

**发现**：`--split border --crop border` 看似能复用 Hough 结果，**但实际不行**：
- split_border 找的是"双页"的左右版框（最外侧）
- crop_to_border 找的是"单页"的版框（更精细）
- 子图只含左/右版框之一，split 的"最外侧"对子图是错的

要做 A3 需改 split_border 返回 `[(left_rect, right_rect), ...]`，crop 接 rect 而非自己跑 Hough。这是**接口级改动**，推迟到 v1.6 重构。

## 关键决策回顾

### 1. A1 薄包装模式（重要）

不是改公共 API，而是加 `*_from_array` 私有变体 + 公共 API 变薄包装。这保证了：
- 65 老 test 零修改
- 第三方代码（GUI、CLI）零修改
- 行为 100% 兼容（像素 bitwise 一致）

### 2. B1 chain(sampled, remaining)

`islice` 消耗 iterator 是隐式行为。首次实现漏掉 chain，小 PDF 输出 0 张，被 D2 测试 `test_empty_pdf_returns_cleanly` 间接暴露（paper_pages=5 但 PDF 只有 5 页）。修后用 chain 保证采样页也在主循环里。

### 3. C1 不动 API

只抽共享模块，不动 caller 接口。理由：
- 行为对等可以用 set 比较 line 集合验证
- 0 风险，可单独 ship

A3 联动需要接口改动（split_border 返回 rect 列表）→ v1.6 重构。
