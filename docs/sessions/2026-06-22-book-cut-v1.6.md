## 概要

v1.5 主要做"性能 + 内存 + per-page paper color"；v1.6 转向"鲁棒性"——回到古籍扫描最常见的两类失败：

## A线（抗伤字 · 切分）

### gutter p95+mean 双判据（commit 00198df 中）

**问题**：原 `split/gutter.py` 用 `col_means = arr.mean(axis=0)` + `min_white_value=220`。
古籍竖排列稀疏（每列 1-2 暗像素）→ mean 200-220 → 被认作"白列" → 切到字符上。

**解决**（proposal §5.1）：
```python
def _column_is_white(col_arr, min_p95=230.0, min_mean=220.0) -> bool:
    f = col_arr.astype(np.float32)
    return (np.percentile(f, 95) >= min_p95) and (f.mean() >= min_mean)
```

**关键判据**：p95 ≥ 230 是"白列最暗的 5% 像素仍 ≥ 230"；稀疏文字列最暗 5% 像素 < 200（被字符拉低）。

**同时收紧默认参数**：
- `search_range` 0.4 → 0.2（只搜中心 ±10%，防远端散点误判）
- `min_run_width` 10 → 20（要求更宽白段）

**ZHSY 回归**：gutter 位置 645 → 720（更接近真实中缝 750）；132 pages 输出、66 outline 节点保留。

## A线（抗伤字 · 裁切）

### border.crop_to_border padding 5 → 10

提案 §3.2 选 A1：翻倍保守。检测本身（`detect_lines`）不变，只调整裁切坐标。

**权衡**（重要）：padding 是"版框线向内裁的偏移量"，所以 padding 越大输出越小（更保守避版框附近的扫描瑕疵）。原 proposal T12 描述"padding=10 保留字符"实际方向相反——padding=10 是更紧的裁切，可能反而裁到贴版框字符。但权衡是：
- padding=5 太激进 → 字符贴版框 < 5px 被裁
- padding=10 适中 → 版框瑕疵不进，但贴版框 5-10px 字符被裁
- padding=15+ 太保守 → 浪费边距

**已知限制**：贴版框 5-10px 字符被裁（漏切 ≪ 误切，故意保守）。用户用 adaptive padding 可微调（v1.3+）。

## B线（抗杂质 · 裁切）

### cv2.morphologyEx(MORPH_OPEN, 3x3)

**效果**（proposal §5.2）：
- 1 像素孤立点 → 清除
- 2 像素短线段 → 清除
- 3×3 实心块 → 保留
- 文字笔画（≥ 4 像素宽）→ 保留

**已知限制**：6pt 注疏（1-2 px 笔画）与尘点物理上不可分。CLI `--no-morph` opt-out 救场。

### safety margin 贴边保护

公式：`max(5, int(min(h, w) * 0.01))`
- 4000×4000 → 40px
- 3000×2000 → 20px
- 500×500 → 5px（floor）

内容边界距图边 < safety → **不裁**（返回原图）。

**权衡**：safety 内的真内容也漏切。漏切 ≪ 误切，故意保守。用户可调 padding 补回。

### min_ink 统一 ≥ 3

- legacy `min_ink=1`（v1.1）→ **3**（v1.6+）
- 与 adaptive `config.min_edge_ink=3` 对齐

**修测试 fixture**：`_page_with_heavy_white_margins` 和 `_page_with_white_margins` 文字行从 `width=2` 改 `width=3`（2px 会被 MORPH_OPEN 当尘点吃掉，与 proposal §5.2 预期一致）。

## 关键决策回顾

### 1. fixture width=2 → 3（测试修改）

原 `_page_with_heavy_white_margins` 文字行 `width=2` → v1.6 MORPH_OPEN 当尘点吃掉。
改 `width=3` 后 ≥ MORPH_OPEN 阈值 → 内容保留。

这是 proposal §5.7 预期行为（"尘点 1px 不再触发"），不是 bug。

### 2. T12 描述与实现不符

proposal T12 描述"padding=5 时字符被裁；padding=10 时保留"，但实际实现里 padding 是"版框线向内裁的偏移量"，padding=10 是**更紧**的裁切（输出更小）。

测试改为验证 API 契约：padding 越大输出越小（更保守）。实际"贴版框字符保护"靠 trim 的 safety margin 兜底（proposal §5.3）。

### 3. 极小字 vs 尘点的物理不可分性

1-2 px 笔画 vs 1-2 px 黑点：物理上无法用纯形态学区分。
- 默认 ON（MORPH_OPEN）：抗尘点，牺牲 6pt 注疏
- --no-morph：保留极小字，牺牲尘点抗性

**用户二选一**，proposal §10 已知限制明确写明。

### 4. safety margin 是保守策略

内容贴图边 < safety → 不裁。safety 内的真内容也会"漏切"。
权衡：漏切 ≪ 误切（古籍扫描里宁愿多留白边也别伤字）。

## 风险与缓解

| 风险 | 缓解 | 状态 |
|---|---|---|
| 极小字（6pt）被 MORPH_OPEN 吃掉 | CLI `--no-morph` opt-out | ✅ |
| safety margin 导致贴边真内容漏切 | "漏切 ≪ 误切" 保守策略；用户可调 padding | ✅ |
| gutter p95 阈值过严 | p95 ≥ 230 + mean ≥ 220 双判据（白列 p95=255 不会拒） | ✅ |
| border padding 10 影响贴版框稀疏图 | padding 仅用于裁切坐标，不影响 Hough 检测 | ✅ |
| 2 老 fixture `width=2` 笔画被 MORPH_OPEN 吃 | 改 `width=3`（≥4px 稳过 MORPH_OPEN） | ✅ |
| `--no-morph` 默认 ON 影响老用户 | 提案明确为 opt-out；GUI 默认勾选开 | ✅ |

## 已知限制

1. **6pt 注疏与尘点物理不可分** —— `--no-morph` 二选一
2. **gutter p95 阈值是经验值** —— 极少数高对比度朱砂可能穿透，配合 `search_range=0.2` 限定
3. **safety margin 是保守策略** —— 贴边真内容漏切
4. **morphology 3×3 核固定** —— 不均匀 DPI 混排不友好（v1.7 候选）
5. **border padding 翻倍 = 更紧裁切** —— 与"贴版框字符保护"权衡（实际保护靠 trim safety margin）
6. **half 切偏靠文档解决** —— 不改算法，CLI help 警告
7. **A3 联动未做**：split+crop border 仍跑 2 次 Hough（推迟到 v1.6 sprint 2 或 v1.7）
