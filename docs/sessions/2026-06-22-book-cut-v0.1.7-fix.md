## 根因

`pypdf` 内部 import `cryptography`（用于 PDF 加密/证书处理的可选依赖），
触发 `OpenSSL 3.0's legacy provider failed to load` fatal error。

macOS 上 Homebrew `openssl@3` 把 legacy provider 拆为独立 formula
（`openssl@3-legacy`），未装时 cryptography 默认 strict 模式即 fatal。
本机 dev 环境（`/opt/homebrew/opt/openssl@3` 4.0.1 含 legacy）不会触发，但
打包后的 .app 运行环境 / 其他 macOS 用户环境可能缺 legacy。

**触发条件**：任何走 `pypdf.PdfReader` / `PdfWriter` 的路径，即开了 `--pdf` 输出。
v1.4 的 outline 注入链路（`_build_writer_from_pdf_bytes`）首当其冲。

## 修复

`src/book_cut/__init__.py` 顶部加：

```python
import os

# cryptography 在 import 时检查 OpenSSL 3.0 legacy provider，未装则 fatal。
# pypdf 内部会 import cryptography，所以 --pdf 路径全炸。setdefault
# 不覆盖用户已设值，且必须在 cryptography 加载前生效——放在 book_cut 包入口。
os.environ.setdefault("CRYPTOGRAPHY_OPENSSL_NO_LEGACY", "1")
```

- `__init__.py` 是 `import book_cut.*` 必经，比 `pypdf` / `cryptography` 加载更早
- `setdefault` 不覆盖用户自定义
- cryptography 官方推荐做法（错误信息中明示）
