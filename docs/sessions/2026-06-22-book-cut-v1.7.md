## 概要

古籍扫描件合并 PDF 时让所有页 page size 一致——告别"封面 3708×3862 / 文本 3424×3330 / 插图页 4288×3330"在 PDF 阅读器里大小跳变的问题。

| 维度 | v1.6 baseline | v1.7 落地 |
|---|---|---|
| 默认 PDF 页面尺寸 | 各图原分辨率（不一致） | **`keep`（默认）/ 预设 / 自定义 / `max` / `first`** |
| `max` 模式开销 | 不支持 | 预扫 PDF 133 页 < 100ms（用 `Page.rect` 不渲染） |
| 图片 fit 策略 | 不需要 | 等比 fit + 居中 paste + 留白填白（mode 跟随子图） |
| GUI 联动 | 无 | combobox 8 选项 + custom 时 W/H/unit 三输入框 enable |
| 测试 | 213 | **228**（+15：8 解析 + 4 fit + 2 真 PDF mediabox + 1 choices） |

**关键设计**：
- 预设表统一 mm 存储（避免 inch/mm/px 混存），转换在 `_mm_to_px` 集中
- `fit_to_canvas` 用 `min(scale_w, scale_h)` 长边贴合目标短边（contain 风格），画布 mode 跟随子图（L / RGB），bg=255 白边
- 子图与 target 同尺寸时 `scale == 1`，等价于 copy

## 2. 流式预扫 `iter_page_sizes`

```python
def iter_page_sizes(source: str | Path) -> Iterator[tuple[int, int]]:
    """流式产出每页 (width, height)，仅取尺寸不渲染。
    - PDF: pymupdf.Page.rect.width/height（points，1pt = 1/72 in）
    - 图片: Image.open(path).size 后 close（不实际 load 像素）
    - 文件夹: 递归
    """
```

**`max` 模式怎么工作**：流水线入口先用 `iter_page_sizes` 流式预扫全部源页 → `max_w = max(w for w, h in sizes)`，`max_h = max(h for w, h in sizes)` → 后续 `_process_one` 用此 `target_size` fit。

**为什么不直接 `first` 近似 max**：v1.7 推荐 `max`（保证所有图都装得下不裁内容），但首页可能是封面（3708×3862）与其他页不一致 → 必须预扫。`iter_page_sizes` 只取 rect / `Image.size`，**不渲染**（比 `get_pixmap` 快 100×+），PDF 133 页 < 100ms 可接受。

**`first` 模式**：直接取第一页尺寸，跳过预扫。

## 3. 流水线接入

`pipeline/orchestrator.py` 入口 `run_pipeline`：

```python
# 1. 解析 --pdf-page-size → target_size: tuple[int, int] | None
target_size = self._resolve_pdf_page_size(source)  # max/first → iter_page_sizes 预扫

# 2. _process_one 末尾在 save_image 前 fit
if target_size is not None:
    page_img = fit_to_canvas(page_img, *target_size, bg=255)
self.save_image(page_img, ...)
```

`target_size is None`（即 `keep`）→ 跳过 fit，零侵入。

## 4. CLI 设计

```bash
# 默认：保持 v1.6 行为
--pdf-page-size keep            # 默认

# 自动：预扫后取 max(W) × max(H)
--pdf-page-size max

# 自动：用首页尺寸（不预扫）
--pdf-page-size first

# 标准预设（mm 内部存储）
--pdf-page-size a4              # 210×297
--pdf-page-size a5              # 148×210
--pdf-page-size letter          # 8.5×11 inch
--pdf-page-size legal           # 8.5×14 inch

# 自定义（必传 --pdf-page-dim + --pdf-page-unit）
--pdf-page-size custom --pdf-page-dim 280x200 --pdf-page-unit mm
--pdf-page-unit {mm,cm,inch,px}  # 仅 custom 生效，mm 为默认
```

**作用域**：仅 `--pdf` 模式生效；非 PDF 模式 → 警告后忽略（图片输出保持原分辨率）。

## 9. 关键决策回顾

### 1. fit 策略选 A（提前 fit）

候选：A 提前 fit / B `img2pdf layout_fun` / C `reportlab` 重写

**选 A 的理由**：后续链路（`save_image` + `save_pdf` + `inject_outline_and_metadata`）零修改，零新依赖。B 要深挖 img2pdf 内部 layout_fun 协议；C 破坏现有 img2pdf 链路 + outline 注入。

### 2. `max` vs `first`

- `max`：保证所有图都装得下（缩放到 ≤ max(W)×max(H)），但比"各自原大"费存储（多 padding）
- `first`：省存储，但首页大 → 其他页被放大；首页小 → 其他页被压缩

**默认推荐 `max`**（最常见的"古籍扫描件多尺寸"场景），用户也可选 `first`。

### 3. fit 风格 = contain（保留全图 + 留白）

而不是 cover（裁掉超长边）。古籍扫描件本来白边多，contain 把内容完整保留，padding 只是"统一画布"。

### 4. `keep` 作为默认（零侵入）

老用户跑 v0.1.8 行为与 v0.1.7 完全一致，只在显式开 `--pdf-page-size {max,first,a4,...}` 时才生效。

### 5. `iter_page_sizes` 不渲染

`pymupdf.Page.rect.width/height` 直接读 PDF mediabox（pt），不 `get_pixmap` 渲染。133 页 < 100ms。`Image.open(path).size` 只读 header，不 load 像素。

### 6. 非 PDF 模式 warn 而不 error

非 `--pdf` 模式开 `--pdf-page-size a4` → 输出本就是 PNG/JPEG 单图，统一尺寸没意义。warn 后忽略而不是直接抛错（用户可能是脚本化调用，warn 更友好）。

### 7. C3 阈值放宽 350 → 400

`pipeline/orchestrator.py` 305 → 371 行（+66 行：max/first 预扫 + fit 步骤）。C3 单文件 ≤ 400 行阈值同步上调。

## 10. 已知限制

1. **fit 策略单一**：只 contain（等比 fit + 留白）。不支持 cover（裁掉超长边）/ fill（拉伸）/ none（居中）
2. **画布留白统一填白（bg=255）**：不支持透明 / 自定义底色
3. **`max` 必须预扫**：百页 PDF 开销 < 100ms，千页 PDF < 1s，可接受；万页 PDF 待测
4. **img2pdf 96 DPI 约定**：自定义 px 时必须按 96 DPI 算（与 img2pdf 默认一致）；其他 DPI 用户要自己换算
5. **非 PDF 模式不生效**：开 `--pdf-page-size` 但关 `--pdf` → warn + 忽略
6. **多 PDF 输入**：当前所有 PDF 共用同一 page size；不支持"每本书独立"

## 11. 风险与缓解

| 风险 | 缓解 | 状态 |
|---|---|---|
| `max` 预扫增加启动开销 | `iter_page_sizes` 不渲染，< 100ms | ✅ |
| fit 后图变小（padding 多） | 默认 `keep` 不 fit；用户主动选 max/first 才生效 | ✅ |
| GUI `custom` 三输入框无校验 | argparse 阶段做格式校验（CLI 必传 dim，否则 error） | ✅ |
| 老用户被 `max` 行为惊到 | 默认 `keep`，零侵入 | ✅ |
| img2pdf layout_fun 协议变更 | 走 A 路径，绕开 img2pdf 内部协议 | ✅ |

## 12. 后续（v1.7+ / v1.8 候选）

- **fit 风格选项**：`--pdf-fit {contain,cover,fill,none}` —— 用户控制是留白 / 裁边 / 拉伸 / 居中不变
- **多 PDF 独立 page size**：每本书一组 `target_size`，按 source_name 分段
- **per-PDF page size preset**：GUI 加 `应用范围` 选 {本本 / 全部}
- **outline 与 page size 同步**：当 `max` 模式变 page size 后，原 PDF outline 的页码仍指向"原图序" → 需 reconcile（v1.8 候选）
- **`max` 预扫缓存**：千页 PDF 二次跑复用前次预扫结果
