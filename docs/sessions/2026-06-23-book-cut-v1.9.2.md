# 2026-06-23 · book-cut v1.9.2 切分/裁切鲁棒性

## 概要

用户用 `samples/尸子卷上下.浙江书局.光绪三年刊_0021.png`（6400×8534 L mode 古籍扫描）测试时发现两个真实问题：

1. **trim 完全不裁** —— v1.8.2 把外侧白边整片保留
2. **border crop 出血** —— v1.8.2 裁到 (4290, 5621)，内容被切碎

定位：古籍扫描**无完整外框 + 边缘零散噪点**。旧逻辑：

- border crop 直接把 Hough 检测到的栏线当外框
- trim safety margin 把边缘噪点当"贴边内容"，放弃裁切

v1.9.2 在实验分支 `v1.9.2-crop-robustness` 上做 3 个修复（A/B/C），共 2 个 commit：

| Commit | 内容 |
|--------|------|
| `bffed5d` | A. border crop 外框候选过滤（最长 dark run ≥ 0.4*dim）<br/>B. trim safety 噪点豁免（longest_run < 100 → 当噪点） |
| `4ff3cda` | C. 新增 `--split none`（输入已是单页，跳过切分） |

## 关键决策

| 子项 | 选 | 拒 | 理由 |
|------|------|------|------|
| border 过滤阈值 | `0.4 * dim` | `0.5 / 0.3` | 0.5 太严（filter reject 真实外框），0.3 太松（filter 失效） |
| 噪点判据 | `longest_run < 100` | `< 50 / < 200` | 古籍边缘噪点 30-70 px；border frame 1000+；栏线 300+；稀疏点 1 |
| 邻域检查 | `±1` 列 max run | 单列 / flatten | PIL outline=2 渲染偏 1-2 px；flatten 会跨列错位 |
| 噪点豁免触发 | safety 严格命中后尝试 relaxed (×0.5) | 直接放弃 / 直接豁免 | 二级 fallback 兼容大多数场景 |
| split=none 实现 | orchestrator 加 `if split_strategy == "none"` 短路 | 新增 strategy 模块 | 改动最小，3 个 caller（CLI/GUI/orchestrator）自然支持 |

## 调试踩坑

### 1. Fix A 第一版用 flatten 错位

```python
return _longest_dark_run(arr[:, lo:hi].flatten())  # ❌
```

`arr[:, 78:81].flatten()` 把 3 列按行展开 → col 80 的连续 dark 像素变成"每 3 个 1 个 dark" → run 断开。

**修正**：取窗口内每列的 run 后 `max`，保留列内连续性。

### 2. Fix B 第一版用 `MIN_CONTENT_RUN=100` 过滤 col_has_content

误以为能从源头排除噪点列 → 8 个合成测试崩（3 px 横线测试被误杀）。

**修正**：保留 `col_has_content = ink_mask.sum(axis=1) >= 3`（min_ink 阈值），把噪点豁免逻辑放在 safety check 层而不是 content detection 层。
